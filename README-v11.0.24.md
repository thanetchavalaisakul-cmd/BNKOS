# BNK School OS v11.0.24 — User Signature Profile & Dynamic Signing

เวอร์ชันนี้เพิ่มโปรไฟล์ลายเซ็นกลางของผู้ใช้งาน และทำให้ระบบที่ 5–6 รองรับลายเซ็นของทีมแบบยืดหยุ่นตามจำนวนครูผู้รับผิดชอบจริง

## ลายเซ็นของฉัน

ผู้ใช้งานมีหน้า **ลายเซ็นของฉัน** โดยเลือกแนวทางลงนามได้ 3 แบบใน UI:

1. **เซ็นบนกระดาษ** — PDF เว้นช่องลายเซ็นไว้ ไม่ใช้ลายเซ็นดิจิทัล
2. **เซ็นสดในระบบ** — วาดด้วยเมาส์/ปากกา/หน้าจอสัมผัส แล้วบันทึกเป็นลายเซ็นหลักได้
3. **อัปโหลดรูปลายเซ็น** — แนะนำ PNG/WebP พื้นหลังโปร่งใส เพื่อวางบนเอกสารได้สะอาด

ลายเซ็นหลักเก็บใน Private Storage `signatures` และเอกสารที่ส่งแล้วใช้ snapshot ของเวอร์ชันนั้น จึงไม่เปลี่ยนย้อนหลังเมื่อผู้ใช้เปลี่ยนลายเซ็นหลักภายหลัง

## Reminder / Checklist

เมื่อเปิดใช้งานบัญชี ระบบยังคงแจ้งเตือนให้บันทึกแฟ้มข้อมูลบุคลากร และเพิ่มการแจ้งเตือน **กรุณาตั้งค่าลายเซ็นของคุณ** หากยังไม่ได้ตั้งค่า

- หากเลือก “เซ็นบนกระดาษ” ถือว่าตั้งค่าแล้ว
- หากมีลายเซ็นดิจิทัลแล้ว การแจ้งเตือนจะถูกปิด
- มีการ backfill แจ้งเตือนให้บัญชีที่เปิดใช้งานอยู่และยังไม่เคยตั้งค่าลายเซ็น

## Auto Sign / Auto Approve + Sign

มี Global Toggle ต่อผู้ใช้:

- **ใช้ลายเซ็นอัตโนมัติกับทุกระบบที่รองรับ**
- **อนุมัติ + ลงนามอัตโนมัติ** — แสดงเฉพาะผู้ที่มีบทบาทหัวหน้า/ผู้ตรวจที่ระบบรองรับ

ข้อกำหนดสำคัญ:

- การเปิดอัตโนมัติครั้งแรกต้องยืนยันรหัสผ่านล่าสุด
- Auto Sign ไม่ส่งงานแทนผู้ใช้ และไม่ข้าม Workflow
- Auto Approve ทำงานเฉพาะช่องที่ผู้ใช้นั้นได้รับมอบหมายจริง และระบบนั้นประกาศ `supports_auto_approve=true`
- ขั้นผู้บริหาร/ผู้อำนวยการยังคงใช้ Central Approval Policy เดิมเป็นหลัก
- สำหรับผู้ตรวจทั่วไป ระบบประมวลผล personal automation เมื่อ session เปิด/รีเฟรช Academic Submission Workspace และหลังบันทึกการตั้งค่า โดยยังตรวจ Workflow ทุกครั้ง
- สำหรับ shared team ของระบบ 5–6 snapshot/Auto Sign ของสมาชิกทีมถูกประมวลผลฝั่งฐานข้อมูลตอนส่งงาน
- ลายเซ็นแบบ Manual จะไม่ถูก Auto Sign เขียนทับ

## Dynamic Shared-Team Signatures

PDF ระบบที่ 5 และระบบที่ 6 จัดตำแหน่งลายเซ็นตามจำนวนครูร่วมโดยอัตโนมัติ:

- 1 คน — กึ่งกลาง
- 2 คน — ซ้าย / ขวา
- 3 คน — ซ้าย / กลาง / ขวา
- 4 คนขึ้นไป — จัด 3 คอลัมน์และขึ้นแถวใหม่อัตโนมัติ

ระบบที่ 5 ใช้ทีม **ครูประจำชั้นร่วม** จาก Assignment กลาง ส่วนระบบที่ 6 ใช้ทีม **ครูที่ปรึกษา/ผู้รับผิดชอบชุมนุม** ของงานนั้นโดยตรง

เมื่อส่งงาน ระบบสร้าง `academic_shared_team_signatures` เป็น snapshot ต่อ `document_version` เพื่อให้ชื่อ ตำแหน่ง วิธีลงนาม และลายเซ็นของทีมในเอกสารเวอร์ชันเก่าไม่เปลี่ยนย้อนหลัง

## Security

- ตารางใหม่เปิด RLS
- authenticated มี SELECT ตาม scope แต่ไม่มี direct INSERT/UPDATE/DELETE
- การแก้ preference ใช้ RPC ที่ตรวจ `auth.uid()`
- RPC ใหม่ revoke `PUBLIC`/`anon` และ grant เฉพาะ `authenticated`/`service_role`
- Auto Sign/Auto Approve ต้องใช้ลายเซ็นของผู้ใช้เอง
- ไฟล์ลายเซ็นยังอยู่ใน Private Storage

Security Advisor ยังแจ้ง warning `authenticated_security_definer_function_executable` สำหรับ RPC ที่ตั้งใจเปิดให้ผู้ใช้ authenticated เรียก โดย RPC ตรวจสิทธิ์ภายในแล้ว จึงไม่ถือว่า Advisor เป็นศูนย์คำเตือน
